# Deliverable 5 — Five-week development roadmap

## Capacity and outcome

Assume two full-time engineers (one backend/security, one ingestion/retrieval), a reviewer available 6–10 hours/week, and security/operations support 4 hours/week. Five weeks provide 400 gross engineering hours. Plan 64 feature hours + 16 integration/risk hours per week, totaling 320 planned + 80 reserve hours. Annotation, enterprise identity/storage approval and policy decisions are real dependencies, not unpaid background work.

The week-5 outcome is a controlled ingestion/search pilot for approved users. Enterprise-wide production, legally reliable contract automation, full handwriting support, an answer assistant and a new GPU inference service are outside that commitment. If only one engineer is available, retain the scope cuts below and expect roughly twice the elapsed time or a materially smaller pilot.

## Gates that cannot be traded for a demo

Before any real confidential content: private approved storage and backups, no external AI/network path, sandbox limits, current malware definitions, real SSO/ACL enforcement, no text in telemetry, source-linked authorized previews, restrictive unknown policy, prompt revocation and deletion blocking, and an incident owner. A mock role selector or localStorage demo is not an acceptable replacement for server-side access control.

Before broader production: restore/delete reconciliation, threat-model review, all [security acceptance tests](06-testing-benchmarking.md) passed, signed retention policy, dependency/model license register, independent security review, measured load capacity, operational playbooks and a documented support owner. The plan does not guarantee these organizational dependencies fit into five weeks.

## Dependency path and cut rules

The critical path is identity/policy → secure storage/jobs/sandbox → canonical source evidence → lexical/vector indexes → lifecycle/revocation → evaluated pilot. Reviewer access and storage approvals start on day 1. If identity is delayed, continue synthetic local testing; do not allow confidential use with a substitute mock identity.

Cut in order: full generative answers, VLM experiments, model-driven contract extraction, reranking, semantic chunking, optional OCR-PDF export, then nonessential review UI polish. Preserve the four input branches, evidence structure and security requirements. If a branch remains unreliable, expose it as unsupported/needs-review rather than silently publishing incomplete content. Do not absorb several new infrastructure services into this schedule.

At the end of each week record actual effort, open blocking dependencies and the next week's scope. A security gate failure can narrow the pilot to synthetic documents while engineering continues; it must not be hidden behind an average extraction score.
