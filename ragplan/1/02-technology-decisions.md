# Deliverable 2 — Technology decision matrix

## Evidence and selection method

These comparisons use upstream documentation and model cards retrieved on 2026-11-15. A supported language is not a validated accuracy guarantee. Latency and memory ranges below are **initial engineering budgets for this project**, not cross-tool benchmark measurements. There is no reliable published comparison matching our Vietnamese/English contracts, CPU configuration, permissions and table questions; [deliverable 6](06-testing-benchmarking.md) defines the deciding local experiment.

Upstream maintenance observations: Docling, PaddleOCR, MinerU, pgvector and Presidio expose live repositories/documentation. This establishes availability, not a support SLA or a security audit. Current PaddleOCR documentation includes PP-OCRv6 and PaddleOCR-VL-1.6; comparisons restricted to PP-OCRv4/v5 or the first PaddleOCR-VL would omit current candidates. Current MinerU documentation includes CPU-capable backends; it is inaccurate to reject all MinerU deployments as GPU-only. [PaddleOCR updates](https://github.com/PaddlePaddle/PaddleOCR), [MinerU current README](https://github.com/opendatalab/MinerU).

## Extraction and OCR

All local options below are suitable for confidential content **only inside the approved isolation/storage boundary**, with remote features and telemetry disabled, dependencies reviewed, and model files prefetched and pinned. A local package name alone is not a privacy control.

| Option | Accuracy/structure and language considerations | CPU-only and initial resources | Integration, license and decision |
| --- | --- | --- | --- |
| **Docling standard pipeline** | Layout/reading-order/table model; native text plus OCR integration. Good baseline for structured output; tables and hierarchy still require validation on our corpus. Language coverage depends on chosen OCR. | **Yes.** Budget 4 CPU threads and 4–8 GiB per worker; GPU optional for throughput. Heavy pages can exceed this budget and must fail safely. | **Primary PDF layout adapter.** MIT toolkit; separately inventory model and dependency licenses. Larger dependency/model footprint than text-only parsing. [Repository](https://github.com/docling-project/docling), [configuration](https://docling-project.github.io/docling/usage/advanced_options/). |
| **pypdfium2 + pdfplumber** | PDFium rendering/text geometry; pdfplumber exposes characters, lines and configurable table extraction. Useful digital fast path and table debugging; does not recover scan text without OCR. | **Yes.** Budget 1–2 threads and 0.5–2 GiB for bounded pages; malformed content can exceed it. | **Primary probing/rendering and digital fallback.** pypdfium2 Apache-2.0/BSD-3-Clause, PDFium and bundled dependencies have notices; pdfplumber MIT. Lower structure recovery than layout models. [PDFium bindings](https://github.com/pypdfium2-team/pypdfium2), [pdfplumber limitations](https://github.com/jsvine/pdfplumber). |
| **python-docx + bounded OOXML inspection** | Styles, paragraphs, lists and native tables; explicit handling needed for merged/omitted cells, nested tables, revisions, fields, shapes and text boxes. No authoritative pagination. Vietnamese/English Unicode text is native data. | **Yes.** Budget 0.5–2 GiB; ZIP/XML expansion limits precede parsing. | **Primary DOCX path**, mapped into our canonical structure. MIT. Use an explicit OOXML adapter where high-level APIs lose detail; retain warnings instead of claiming complete support. [Library](https://python-docx.readthedocs.io/en/latest/), [table semantics](https://python-docx.readthedocs.io/en/latest/user/tables.html), [license](https://github.com/python-openxml/python-docx/blob/master/LICENSE). |
| **pypdf** | Lightweight metadata, encryption/structure checks and native text fallback. PDF does not guarantee semantic order; decompressed streams can be very large. | **Yes.** Process-limited, never inline in API. | BSD-style permissive license. Optional alternative probe; do not add a third PDF engine unless it fixes measured failures. [Extraction caveats](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [license](https://github.com/py-pdf/pypdf/blob/main/LICENSE). |
| **PyMuPDF** | Efficient rendering, text/geometry and extraction features; useful alternative if its behavior wins on our corpus. OCR remains a distinct engine/workload. | **Yes.** CPU rendering/native extraction; OCR adds resources. | **Fallback after license decision**, not a silent default dependency. AGPL or commercial terms; confidential processing can be local, but license suitability must be reviewed for the actual deployment/distribution. Do not assert every internal use mandates publication. [Official licensing](https://pymupdf.readthedocs.io/en/latest/about.html). |
| **Tesseract with eng+vie** | Mature printed-text baseline; preserve word boxes and raw confidence. Poor handwriting, stamps over text and degraded diacritics remain risks. No table topology by itself. | **Yes.** Budget 1–4 threads and 1–3 GiB including page raster; starts cheaply at low volume. | **Primary OCR baseline** inside Docling or a region adapter. Apache-2.0. Benchmark `tessdata_fast` and `tessdata_best`; neither is universally best for our workload. [Engine](https://github.com/tesseract-ocr/tesseract), [English/Vietnamese data](https://tesseract-ocr.github.io/tessdoc/Data-Files-in-different-versions.html). |
| **PaddleOCR conventional OCR / PP-StructureV3** | Current conventional PP-OCRv6 candidate; v5 multilingual docs explicitly list Vietnamese and API language code `vi`. PP-StructureV3 produces layout/table output. Validate the exact recognition model's language coverage and fine-grained boxes. | **Yes for conventional OCR/structure paths.** Budget 2–4 threads, 2–6 GiB; GPU optional. Model/backend combinations vary. | **First OCR/layout challenger**, promote if it meets fidelity and operational gates. Apache-2.0 project; audit weights separately. Paddle runtime increases deployment complexity. [Current project](https://github.com/PaddlePaddle/PaddleOCR), [language models](https://www.paddleocr.ai/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html), [OCR API](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/OCR.html). |
| **OCRmyPDF** | Adds searchable text to PDFs; useful derivative for legacy viewers. It is not a canonical layout/table extractor or a sanitizer. Signed originals must remain unchanged. | **Yes.** Tesseract, PDF tooling, raster/temp storage; budget similar to OCR plus conversion overhead. | **Optional derivative only.** MPL-2.0 project, transitive tools such as Ghostscript have their own license terms. Avoid adding this to every job. [Security and signature behavior](https://ocrmypdf.readthedocs.io/en/latest/pdfsecurity.html), [project license](https://github.com/ocrmypdf/OCRmyPDF/blob/main/LICENSE). |
| **MinerU current local tiers** | Alternative structured parser with OCR/VLM paths. Evaluate full geometry and table outputs, not Markdown appearance alone. Verify Vietnamese on actual scans; model coverage is not established here. | **Yes for documented CPU paths.** Upstream lists basic ONNX around 2 GB RAM and standard ONNX+llama.cpp around 8 GB; accelerated variants list 8 GB+ VRAM. These are upstream tier figures, not our measured end-to-end footprint. | **Challenger, not MVP dependency.** Current license is Apache-based **with additional commercial thresholds and attribution terms**; older AGPL descriptions and plain-Apache descriptions can both be misleading for current HEAD. Review pinned release and weights. [Current requirements](https://github.com/opendatalab/MinerU), [actual license](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md). |

Do not infer signed/executed legal status from an OCR signature image, stamp, VLM description or detected signature field. Cryptographic PDF signature checking would be a separately scoped validation service with certificate-chain, revocation, timestamp and trust-policy handling. It is outside this MVP.

## VLM and cloud alternatives

| Option | Value and limits | CPU/GPU and cost profile | Recommendation and confidentiality |
| --- | --- | --- | --- |
| **No VLM** | Native parsing plus OCR/layout retains literal source evidence and predictable fallback behavior. May still miss complex tables or spatial associations. | **CPU-only**; no generative serving cost. | **Primary MVP.** Human review remains available when automatic extraction fails. |
| **GraniteDocling 258M** | Small specialist producing document structure; model card is English-tagged. Do not assume validated Vietnamese capability. Small size does not eliminate hallucinated text or omitted rows. | CPU experimentation possible; budget 4–8 GiB RAM, or start a GPU trial at 4–8 GiB VRAM and measure actual peak. These budgets are estimates. | Local trial for hard English pages, not a default. Apache-2.0 model. [Model card and limitations](https://huggingface.co/ibm-granite/granite-docling-258M). |
| **PaddleOCR-VL-1.6, 0.9B** | Current specialist alternative with structured document output. Compare literal text, numerical cells and locator coverage. Published aggregate benchmark scores do not establish Vietnamese contract correctness. | Accelerated inference preferred; start trial with 8–12 GiB VRAM and 16 GiB host RAM. CPU backend compatibility and latency must be proven before a CPU promise. | Preferred multilingual VLM challenger after conventional paths. Apache-2.0 model card; review custom model code and pinned artifacts. [Model card](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6). |
| **General local VLM, multi-billion parameters** | Useful for visual relationships/figures; weak fit when literal transcription and precise cell evidence are required. No reason to run one for ordinary digital text. | GPU and KV-cache/image-token cost can dominate; a proposed 7B trial would need a separately measured serving budget. | Defer; no justified default model selection. A quantized weight size is not the runtime memory requirement. |
| **Google Document AI OCR/Layout Parser** | Managed extraction; OCR lists Vietnamese. Current layout documentation describes a Gemini-based parser. Processor version, output grounding, region and quality must be checked separately. | No local GPU; paid page requests, network latency and quotas. | Economic comparator only; **disabled** without enterprise approval. A cloud OCR API is still third-party document disclosure, even without a conversational LLM. [Processor/language list](https://docs.cloud.google.com/document-ai/docs/processors-list), [layout parser](https://docs.cloud.google.com/document-ai/docs/layout-parse-chunk), [pricing](https://cloud.google.com/products/document-ai/pricing). |
| **Amazon Textract** | Managed forms/tables/layout; current language list is broader than historical six-language OCR descriptions, but does not list Vietnamese. Some features have narrower language coverage. | No local GPU; network/API cost and AWS operations. | Not preferred for this bilingual corpus; disabled under the same disclosure policy. Do not assume English feature support implies Vietnamese. [Current service limits](https://docs.aws.amazon.com/textract/latest/dg/limits-document.html). |

Enable a VLM only for a failed page/region after a preprocessing retry and alternate conventional OCR/layout pass. Require an offline paired test with at least a 5 percentage-point improvement in exact critical-cell accuracy on that hard subset, no increase in unsupported facts, and adequate locator coverage. A VLM that cannot provide precise cell/text locations cannot publish exact numeric contract facts automatically. Human confirmation can supply missing evidence links. Cap VLM fallback to 5% of pages initially; overflow enters review rather than spilling to a cloud API.

## Classification, PII, embedding, and storage

| Component | Primary | Fallback / promotion condition | CPU and integration trade-off |
| --- | --- | --- | --- |
| File validation | libmagic/content sniffing, bounded ZIP/OOXML/PDF structure probes, ClamAV, disposable sandbox | Manual rejection/reupload; approved alternate parser only for structural faults | **CPU.** Antivirus updates need a separate download channel; scanner limits/timeouts are failures, not clean scans. [OWASP upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), [ClamAV configuration](https://docs.clamav.net/manual/Usage/Configuration.html). |
| Type classifier | Vietnamese/English title/section/template rules, metadata as weak evidence, explicit `unknown` | Character/word TF-IDF + calibrated logistic regression once labeled data exists; local LLM experiment later | **CPU.** Rules are explainable and cheap; templates overfit. Learned classifier needs held-out local data and abstention. [Text feature extraction](https://scikit-learn.org/stable/modules/feature_extraction.html), [calibration](https://scikit-learn.org/stable/modules/calibration.html). |
| Sensitivity authority | Trusted source labels + business policy + authorized reviewer; machine signals can escalate | Unknown → restricted; reviewer override with reason and version check | **CPU.** No model can infer all business obligations from content. Classification confidence never authorizes export. |
| PII detection | Presidio orchestration, local English NER, bilingual regex/context rules, employee/party dictionaries, custom company recognizers | VnCoreNLP Vietnamese NER adapter if its license/quality pass review; local model-assisted candidates, then human review | **CPU.** Presidio is MIT, now under data-privacy-stack stewardship; default language setup is English. Vietnamese requires real recognizers and offset mapping. VnCoreNLP uses a Java runtime and GPL-3.0-or-later terms. No automatic detector finds everything. [Language extension](https://github.com/data-privacy-stack/presidio/blob/main/docs/analyzer/languages.md), [FAQ](https://presidio.dataprivacystack.org/faq/), [VnCoreNLP](https://github.com/vncorenlp/VnCoreNLP), [license](https://github.com/vncorenlp/VnCoreNLP/blob/master/LICENSE.md). |
| Embedding | **multilingual-e5-small**, 384 dimensions, query/passage prefixes, normalized dense vectors | **BGE-M3**, 1,024 dimensions, if bilingual/cross-language retrieval materially improves | **CPU for both**; reserve 1–2 GiB for E5-small and 4–8 GiB for BGE trial. MIT model cards. E5 limit is 512 model tokens including prefix/context; BGE's longer limit is not a reason for giant chunks. Evaluate Vietnamese rather than relying on multilingual marketing. [E5-small](https://huggingface.co/intfloat/multilingual-e5-small), [BGE-M3](https://huggingface.co/BAAI/bge-m3). |
| Chunking | Heading/clause/layout-aware boundaries; table rows with repeated headers; parent references | Semantic split experiment only if measured retrieval gains exceed extra embedding/complexity | **CPU.** Docling HybridChunker is a useful adapter; our ACL/source invariants still apply. [Chunking design](https://docling-project.github.io/docling/concepts/chunking/). |
| Keyword/vector retrieval | PostgreSQL full-text `simple` configuration plus exact identifiers/numeric filters; pgvector cosine; reciprocal rank fusion | HNSW + iterative scans after scale tests; actual BM25/search engine only after a lexical recall problem | **CPU.** PostgreSQL `ts_rank_cd` is not BM25. Vietnamese syllable tokenization is a starting baseline; accent-folded/trigram projection is a separate search aid, never a replacement for evidence. [PostgreSQL FTS](https://www.postgresql.org/docs/current/textsearch-intro.html), [pgvector](https://github.com/pgvector/pgvector). |
| Reranker | None initially; RRF and deterministic deduplication | Local BGE-reranker-v2-m3 for top 20 authorized pairs if nDCG gain justifies p95 latency | **CPU possible**, 4–8 GiB trial reserve; GPU helps. Apache-2.0 model. Scores rank relevance, not factual confidence. [Model card](https://huggingface.co/BAAI/bge-reranker-v2-m3). |
| Relational/vector store | Supported PostgreSQL 18 release + compatible reviewed pgvector release; exact vectors first | Separate tenant DB for stronger isolation; Qdrant only if vector scale warrants another service | **CPU.** PostgreSQL/pgvector use permissive PostgreSQL-style licenses; Qdrant is Apache-2.0 but needs its own secured API and permission synchronization. [RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html), [Qdrant deployment warning](https://github.com/qdrant/qdrant). |
| Blob storage | Existing approved private object store; encrypted filesystem adapter for single-host pilot | Approved S3-compatible deployment with versioning/lifecycle and separate credentials | **CPU.** Do not add a new distributed storage service solely for the demo. Bucket versioning means delete markers do not erase old versions. [S3 version behavior](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html). |
| Jobs | PostgreSQL jobs table, `SKIP LOCKED`, leases, heartbeats, bounded retry, persistent checkpoints | Celery with an approved broker if queues/worker scheduling outgrow this design; Valkey is a BSD-licensed broker candidate, compatibility must be tested | **CPU.** Small queue removes a service but requires real lease/recovery tests. FastAPI BackgroundTasks is not the ingestion durability mechanism. [PostgreSQL locking](https://www.postgresql.org/docs/current/sql-select.html), [Celery task semantics](https://docs.celeryq.dev/en/stable/userguide/tasks.html), [Valkey](https://github.com/valkey-io/valkey), [FastAPI caveat](https://fastapi.tiangolo.com/tutorial/background-tasks/). |

Presidio/NER detects entities; sensitivity policy decides their significance. Preserve party names and amounts for appropriately authorized contract search. Use reversible pseudonyms only for a specific approved rendition, with tenant-scoped tokens and a separately encrypted mapping vault. Do not install a heavyweight classifier or VLM merely to recognize fixed ID formats.

## Cost per 100 and 1,000 documents

All figures are USD. Normalize to **10 pages/document**, 8 chunks/page, and an assumed local embedding time of 0.03 seconds/chunk. Assumed CPU worker allocation: $0.12 per occupied wall-hour; GPU allocation: $0.75/hour. These rates and processing times are **illustrative planning inputs, not provider quotations or measurements**. The CPU rate is for the whole reserved worker, not per core. Scenarios are alternatives; do not sum all rows.

| Scenario | Assumed processing work | 100 docs / 1,000 pages | 1,000 docs / 10,000 pages |
| --- | --- | ---: | ---: |
| Native simple PDF fast path | 0.5 CPU seconds/page + shared overhead | $0.03 | $0.35 |
| Local layout parser, digital pages | 4 CPU seconds/page + shared overhead | $0.15 | $1.51 |
| Local OCR + layout, all scanned | 14 CPU seconds/page + shared overhead | $0.48 | $4.85 |
| Local scan path + VLM retry on 5% pages | Above + 20 GPU seconds/fallback page | $0.69 | $6.93 |
| Local VLM for every page | 20 GPU seconds/page + CPU shared overhead | $4.18 | $41.85 |
| Cloud OCR + local layout | Gross $1.50/1,000 pages + local layout/overhead | $1.65 | $16.51 |
| Cloud Layout Parser | $10/1,000 pages + local shared overhead | $10.02 | $100.18 |
| Illustrative hosted VLM, no selected provider | 4,000 input + 750 output tokens/page; assumed $0.50/$2.00 per million, plus CPU overhead | $3.52 | $35.18 |

Shared CPU overhead = 3 seconds/document + embedding work. All stage seconds in this model mean occupied worker wall time, not summed CPU-core time; a four-thread worker is charged once at the worker hourly rate. The cloud OCR/layout list prices are from [Google's price page](https://cloud.google.com/products/document-ai/pricing); the OCR calculation deliberately ignores any free allowance, committed discounts and add-ons. The token-priced VLM row is a sensitivity example only; image tokenization, minimum image charges and retries depend on the selected provider. It is not an offer to use that provider or an assertion that this price is available.

These are incremental processing allocations. A continuously reserved $0.12/hour host is $87.60/month at 730 hours even if idle. An illustrative $30/month combined storage/backup allowance makes $117.60/month before labor, identity, security operations, commercial licenses, tax and redundancy. Do not add CPU occupancy charges again if already paying for that same host. A continuously reserved GPU at the example rate would be $547.50/month; sparse fallback utilization does not make idle hardware free.

Human review can dominate: 10% of documents × 2 minutes × $18/hour costs **$6 / $60** for 100 / 1,000 documents. If all labels are unknown and require review, the same assumption becomes **$60 / $600**. For 1,000 documents/month on the illustrative reserved host, local scanned processing plus 10% review has a budget floor around $177.60/month, excluding the other items above; CPU processing is already inside the host cost.

Time sensitivity: multiply assumed stage timings by 0.5×, 2× and 5×, then measure throughput under actual concurrency. At 14 seconds/page plus shared overhead, 1,000 ten-page scans take about **40.4 worker wall-hours** sequentially. A single page with a timeout or enormous table can dominate tail latency. [Machine-readable assumptions](research/cost-assumptions.json) and [unrounded scenario calculations](research/cost-scenarios.csv) make these estimates reproducible.
