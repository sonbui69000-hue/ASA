# Algorithm and technology decisions

Reconciled contract 2.2.0; date and gate reassessment: 2026-11-16. **No extraction, retrieval or model benchmark was run for this package.** Benefits below are mechanisms or hypotheses, never invented percentage gains. `Implement Now` means include in the first authorized implementation; `Experiment` means a bounded comparison to inform selection or qualify that capability before its promotion, **not** a universal prerequisite to baseline implementation; `Design for Later` means concrete interfaces/data hooks now but no runtime dependency; `Reject` means reject as launch/default behavior for a stated reason, not a claim that the technique is universally ineffective. [RB30–RB36](rag-readiness-assessment.md#category-5-noncritical-improvements-and-feature-specific-gates) distinguish optional improvements from baseline gates; core quality/security tests are produced during implementation.

## How to read the matrix

Each row answers all ten requested dimensions: **(1)** failure; **(2)** alternatives/current proposal; **(3)** expected benefit and evidence; **(4)** Vietnamese/English fit; **(5)** CPU/RAM/latency/integration; **(6)** security/privacy/license; **(7)** implementation/maintenance complexity; **(8)** invalidation condition; **(9)** later rework; **(10)** recommendation. Columns combine these dimensions without omitting them.

Cost profiles are initial **budgets, not measurements**: C0 = deterministic CPU code, no model, target <100 ms on a bounded request, metadata RAM; C1 = native parse per bounded page/process, 1–2 threads, 0.5–2 GiB; C2 = OCR/layout worker, 4 threads, up to 8 GiB, seconds to minutes/page; C3 = local E5, 2 threads, up to 2 GiB, target query encode <200 ms warm; C4 = serial larger-model experiment, 4 threads, 4–8 GiB, potentially seconds/query; C5 = VLM/LLM experiment, separate approved memory/GPU envelope, seconds to minutes. Model-specific limits override these classes, not the host memory cap. Complex integration often matters more than floating-point compute.

Security/license profiles: L0 = application-owned deterministic code, no new upstream license; L1 = local reviewed permissive package/model, exact release + transitive weights still gated; L2 = conditional/copyleft or unresolved artifact terms, deployment approval required; L3 = local generative weights/runtime license must be individually approved. All profiles inherit no enterprise egress, authorization before candidate content leaves DB, sensitive outputs and no plaintext telemetry. Source identifiers refer to [primary evidence](research-sources.md); algorithm ideas themselves do not confer a software/model license.
