### How the current evaluation could mislead

| Evaluation dimension | Pass-with-poor-behavior or misleading-failure case | Required change / proposed acceptance |
| --- | --- | --- |
| Corpus distribution | A ~600-page/120-doc corpus averages five pages and can omit 200-page scans while all mean parsing gates pass. Synthetic clean templates underrepresent stamps, copying artifacts and amendment ambiguity. | Add explicit 200/300-page long-tail fixtures and a separately authorized local real holdout for real-world claims. Publish a support matrix including rejected/reviewed cases. No imported workbook reuse. |
| VI/EN/cross-language coverage | Overall scores hide low-quality scanned Vietnamese and cross-language exact-ID failures; ≥20 cases per language cannot validate every language×format×quality×task cell. | Freeze a slice coverage matrix; label sparse cells unestablished and keep review. Cross-language includes both directions and mixed evidence. Report numerators, denominators and family-clustered intervals. |
| Retrieval ground truth | Treating twenty interchangeable citations as jointly required makes a correct answer fail Recall@10. Labeling one convenient passage misses indispensable exceptions. | T13/HR13: OR-of-complete-bundles gold, AND within bundle, separate ranking relevance and sufficiency. Pool candidates from all frozen arms for adjudication; do not reward overlap duplicates. |
| Recall/MRR/nDCG | High first-hit MRR or related-context nDCG can coexist with missing condition/footnote. Candidate truncation loss is hidden by scoring only returned hits. | Report raw channel recall, admitted candidate recall, final unique evidence recall, any-complete-bundle success, then final answer support. Required qualifier absence is a task failure, not grade1 success. |
| Entity/fact metrics | Mention recall can pass while party linking falsely merges two people; money literal is correct but assigned to the wrong installment. | Exact accepted link precision and false merges, typed scope/value+currency+party+condition exactness, current acceptance and link undo. No known false critical merge/value accepted in holdout. |
| Table reconstruction | TEDS/header F1 can pass with one critical swapped amount; nested/continued tables may be excluded as unsupported after inspection. | Score anchor/span/header/footnote/text and exact source-associated critical values; include failures in end-to-end denominators. A supported pattern with wrong auto-accepted critical value disables that rule pending new validation. |
| OCR confidence | High confidence or two agreeing engines can both produce the same wrong monetary digit. | Gold-planted correlated errors, visible/raw disagreement and exact critical-field checks. Calibrate acceptance by rule/template/source quality, not OCR confidence alone. |
| Citation correctness | Every locator resolves while claim swaps party, due condition, currency or effective source. | Separate 100% resolver integrity from adjudicated semantic support. Use wrong-party/negation/exception/current-amendment negatives and semantic retraction races. |
| Abstention/coverage | An all-abstain system has no unsupported claims; a one-answer-only system can report 100% support precision. “Coverage reported” alone does not reject it. | Proposed product gate to ratify: ≥80% supported complete answers on supported answerable tasks overall and ≥70% each established major slice, while retaining original exact identifier/table ≥95% task target and critical error bans. If unrealistic, narrow the promised task set explicitly. These are proposed thresholds, not measured or already approved requirements. |
| Statistical uncertainty | 20/20 correct point precision does not establish 99% reliability; correlated cells in one table are not independent examples. | For each automated critical acceptance rule use a prespecified upper error bound at 95% confidence or keep human review. Rough zero-error 0.5% bound needs ~600 independent cases; cluster by family and show uncertainty when fewer. Existing plan acknowledges this; make it executable per promoted rule. |
| Security | Ordinary endpoint ACL negatives can pass while staged review, final transport/journal faults, aliases or helper roles leak. | ST01–ST21 using actual roles/pool/sandbox/journal; forbidden outputs counted separately with zero tolerance in the finite suite. Never average security failure into retrieval quality. |
| Ablations | Tuning different candidate counts/token budgets or giving one model corrected canonical text makes the comparison unfair. Repeated holdout exposure overfits optional-arm choices. | One factor per arm; frozen bytes/canonical, principals/time, candidate/context budgets and hardware; validation-only tuning; family-clustered paired intervals; new held-out set after post-failure tuning. Log all arms, not winners only. |

T13 is an evaluator self-test, not a retrieval benchmark. T14 tests the safety fallback: reviewers must identify planted wrong digits/header associations in blinded cases, with adjudication and observed review time. Human acceptance must not be treated as infallible training gold merely because it is human.

Model memory is not weight-file size. SQL `work_mem` multiplies by operations/concurrency; parser child limits do not cap the API/DB/model total. Track cgroup plus host memory, DB buffers, sort spills, page cache, WAL, artifact copies/backups, fragmentation and free-disk headroom. Antivirus fail-closed behavior is safe but affects availability; measure update failure recovery and backlog rather than bypassing scanning.

## Approval and closure rules

Before dependent implementation freeze: approve G1's exact domain/API/policy/profile deltas and resolve G2's failure-model choice. Materialize schemas and decisive minimal tests while preserving original docs for comparison. G3–G5 evidence is then produced during implementation and required before the corresponding claims/releases. No requirement exists to have all final benchmarks before building the harness.

A finding closes only when its approved correction, consumer contract and required test agree. “Documented”, “scaffolded”, “test discovered” and “test passed” are distinct statuses. A waived capability must be explicitly disabled/review-only with matching product/API behavior, not silently removed from evaluation. Reopening a security/contract defect blocks its unsafe consumer immediately; optional model experiments can remain not executed.
