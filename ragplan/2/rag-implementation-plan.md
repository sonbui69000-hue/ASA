# Implementation blueprint and release decision

Date: 2026-11-16. **Planning only; do not start production code from this document without a separate implementation instruction and the applicable approval gates.** Reconciled contract 2.2.0 replaces the greenfield assumption/five-week promise in the earlier handoff. The existing demo, imported local data, package locks, environment and production code remain unchanged.

## Scope and dependencies

Build the enterprise document context under future root `services/enterprise-rag/`; reuse reviewed React primitives in a separate enterprise entry point/origin. The existing Node service remains sole authority for its four business modules; offline persistence remains localStorage. No automatic legacy/real-data sync. Initial launch = secure local PDF/DOCX ingestion, review, canonical/table/entity evidence, lexical/exact/multilingual dense hybrid search, exact citations, evidence excerpts/fact-template answers, lifecycle/backup operations. No external enterprise inference, universal converters, legal-signature verification, redacted-only release, arbitrary section ACLs or free-form generator dependency in launch.

Two implementation tracks replace the earlier circular approval/benchmark gate:

1. **Validation track:** P00 contracts/fixtures plus targeted P01–P07 disposable SQL/RLS, parser/source-map, E5, job-fencing and response-barrier spikes. Use synthetic data and documented provisional assumptions; satisfy the minimum environment/asset/sandbox prerequisite for the specific run. A live enterprise IdP, legacy import, real-corpus permission, every candidate model and full pilot hardware are not prerequisites to all these experiments.
2. **Baseline integration track:** approve A01 service/initial scope, A02a tenant boundary, A03 staged/family authority and A09 singleton envelope before permanent service integration/security schema freeze; then follow `P00 → P01 → P02 → P03 → P04 → P05 → P06 → P07 → P08 → P09`. Edges express interface/data dependencies and component acceptance, not a requirement to have later runtime evidence before writing the earlier components that produce it. Prepare independent modules/tests while another integration is waiting. Live identity configuration, real-data policy and operational provisioning attach to their consumers.

Lifecycle primitives/tests begin early; P07/P09 complete integration rather than introduce security for the first time. P10 experiments use frozen P04/P06 outputs when justified by the failure taxonomy. Optional A07 migration and optional A08 free synthesis are outside the baseline critical path. Detailed gate ownership and scope are in [RB01–RB40](rag-readiness-assessment.md).

H: allow roughly 640–1,000 engineering hours for the complete revised scope plus a provisional 80–120 reviewer/annotation hours (withdrawn as a capacity promise; T14/A11 must size it) and 40–80 security/operations hours. These are broad planning estimates, not a delivery commitment or measured implementation effort. Two engineers do not eliminate identity/residency/reviewer dependencies. Maintain 20% integration reserve and re-estimate after P03 and actual OCR/annotation timings. A five-week outcome can only be a narrower synthetic vertical slice if resources/governance delay later gates.
