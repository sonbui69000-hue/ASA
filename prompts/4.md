## Mandatory Automated Testing

Use the installed Playwright skill and the project's Playwright test framework for end-to-end verification.

Use Vitest and React Testing Library for unit, service, and component tests.

### Playwright

Create persistent automated browser tests under tests/e2e/.

Cover:
- Uniform request submission and fulfillment
- Purchasing and approval workflows
- Document search and citation navigation
- Document permission restrictions
- Locker allocation and release
- Shared chatbot interactions
- Role switching
- localStorage persistence after reload
- Reset demo data

Run tests against the actual locally running application.

Test desktop and mobile viewport layouts.

Capture screenshots for the main dashboard, all four modules, and the assistant interface.

Check for:
- Browser console errors
- Failed network requests
- Horizontal overflow
- Broken navigation
- Unresponsive controls
- Incorrect status transitions
- Inconsistent application state

### Vitest

Run the complete unit and component test suite.

Add regression tests for every business-logic defect discovered during QA.

### Execution Requirements

Run:
- TypeScript checks
- Production build
- Vitest suite
- Playwright suite

Fix discovered failures and rerun the affected tests.

If browser execution is unavailable, clearly distinguish:
- Tests that passed
- Tests that failed
- Tests that could not execute

Do not replace real browser verification with a claim that the build succeeded.

### Final QA Report

Provide:
- Total tests passed, failed, and skipped
- Browser scenarios actually executed
- Screenshots captured and their locations
- Remaining defects
- Unverified functionality
- Final build status

Fix discovered issues rather than only listing them.

Do not report tests as passed unless they were actually executed successfully.

At completion, provide:
1. Implemented feature summary
2. Tests executed and results
