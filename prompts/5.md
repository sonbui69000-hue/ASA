Prepare the application for a polished 10-minute live demonstration to Vinmec hospital stakeholders.

The application is a fictional prototype, not a production system.

## Objectives

Make the demo coherent, realistic, visually polished, and easy to understand.

## Final Visual and Demo Verification

Use UI/UX Pro Max to review and refine the final interface.

Use Playwright to inspect the application at desktop and mobile viewport sizes.

Capture screenshots of:
- Dashboard
- Uniform Management
- Document Lookup
- Locker Management
- Purchase Support
- Shared AI assistant
- Approval workflow

Inspect screenshots for layout inconsistencies, clipping, unreadable tables, excessive whitespace, and broken responsive behavior.

Use a fresh, reproducible demo dataset for final verification.

Run all five demo scenarios using Playwright where possible.

Verify that each scenario begins from the intended state and produces the expected outcome.

Avoid major architectural changes during this final phase. Prioritize stability, visual polish, and demonstration reliability.

### Demo Data

Create a consistent fictional dataset including:
- Multiple hospital departments
- Employees with different roles
- Uniform products with realistic size variations
- Inventory shortages and sufficient-stock scenarios
- Employees eligible and ineligible for reissuance
- Pending and completed approvals
- Fictional contracts and internal regulations
- Lockers across multiple buildings and floors
- Mock SAP supplier catalogs
- Purchase requests and simulated POs
- Historical transactions and audit logs

All names, contracts, prices, IDs, and records must be synthetic.

### Demo Scenarios

Create five guided scenarios:

1. A department requests uniforms for several employees.
2. The system detects insufficient stock and prepares a purchasing request.
3. A user searches a fictional contract using the AI assistant and opens the cited passage.
4. An administrator allocates lockers to a group of employees.
5. A purchasing employee searches for an uncertain SAP product match and confirms the correct supplier code.

Each scenario must have predictable starting data and a clear successful outcome.

### UI Refinement

- Improve spacing, typography, alignment, and visual consistency.
- Eliminate awkward layouts and overflowing content.
- Make tables readable.
- Add meaningful empty states and notifications.
- Ensure approval and validation messages are understandable.
- Ensure the interface feels like a coherent enterprise product.
- Clearly distinguish mock integrations from real connected services.

### Demo Controls

Implement:
- Reset demo data
- Role switching
- Predefined demo scenarios
- Seed data initialization
- Clear simulation labels for SAP and AI

Avoid adding unnecessary features that distract from the main workflows.

### Documentation

Create:
- docs/demo-guide.md — step-by-step 10-minute demonstration script
- docs/demo-data.md — key fictional employees, products, contracts, and scenarios
- docs/limitations.md — what is simulated and what would be required for production

Finally, verify that the application starts, builds, and supports all five demo scenarios.

Do not claim the system is production-ready.
