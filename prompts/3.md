Now implement and refine the shared AI assistant.

The assistant must function as a conversational interface to the application's existing mock services and data.

It must not be a decorative chatbot with generic canned responses.

## Interface

- Floating assistant accessible from every page
- Expandable chat panel
- Conversation history within the current demo session
- Suggested questions
- Vietnamese responses
- Source references
- Links to relevant application pages and records
- Clear loading, empty, error, and unsupported-query states

## Architecture

Create a local deterministic intent-routing system.

Suggested intents:
- DOCUMENT_SEARCH
- DOCUMENT_QUESTION
- UNIFORM_INVENTORY
- UNIFORM_ELIGIBILITY
- UNIFORM_HISTORY
- UNIFORM_POLICY
- LOCKER_AVAILABILITY
- LOCKER_ASSIGNMENT
- PRODUCT_SEARCH
- SUPPLIER_MATCH
- PURCHASE_STATUS
- APPROVAL_STATUS
- GENERAL_HELP

The assistant should:
1. Interpret the user's question.
2. Identify the relevant intent.
3. Extract parameters such as employee, department, product, size, or location.
4. Call the appropriate mock service.
5. Generate a response based on returned data.
6. Include evidence, record references, or links where available.
7. Respect the selected user's simulated permissions.

Use simple intent matching, keyword extraction, fuzzy matching, and structured response templates.

No external AI APIs are necessary.

## Document Retrieval

Implement local retrieval against the fictional document collection.

- Search document content, not just titles.
- Return relevant passages.
- Include document name, version, and section references.
- Allow users to open the cited document.
- Do not cite nonexistent content.
- Never reveal unauthorized documents.
- If evidence is insufficient, explicitly say so.

## Important Rules

- The assistant must use current application state.
- If inventory changes, answers must reflect the new quantity.
- If a locker is assigned, it must no longer appear available.
- If a request is approved, the assistant must report its updated status.
- Never invent quantities, employee records, document passages, or SAP codes.
- Never bypass simulated RBAC.
- For uncertain product matches, present candidates and request confirmation.
- For actions that modify data, require explicit user confirmation and route through the same validated service methods used by the normal UI.
- Do not simulate successful actions without updating application state.

## Testing

Create automated tests for intent routing, data retrieval, citations, permissions, and state consistency.

Include at least 20 representative Vietnamese questions.

The assistant should demonstrate meaningful integration across modules while remaining clearly labeled as a simulated AI experience.

## Test Implementation

Use Vitest for automated assistant tests.

Create table-driven tests covering at least 20 representative Vietnamese questions.

Test:
- Intent classification
- Parameter extraction
- Ambiguous queries
- Missing information
- Unauthorized document access
- Correct document citations
- Inventory queries after state changes
- Unsupported requests
- Product-code matching
- Approval-status retrieval

Use deterministic fixtures and assert specific expected records, values, and citations rather than only checking that responses contain text.

Use React Testing Library for the chat interface and Playwright for at least one complete browser-based assistant interaction.

Do not introduce a real LLM API or external inference dependency.
