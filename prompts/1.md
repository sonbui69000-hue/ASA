You are a Senior Full-Stack Engineer, Product Designer, and Enterprise Application Architect.

Your task is to build a polished, fully interactive prototype of a modular hospital administrative web application for Vinmec.

The project proposal DOCX is available in the repository. Read it completely before beginning. Treat it as the primary source of functional requirements.

## Project Objective

Build a realistic, presentation-ready web application demonstrating how the proposed administrative Super App would work in a hospital environment.

This is a **functional prototype, not a production application**.

All data and external integrations must be simulated. No real hospital information, SAP credentials, external APIs, or production services are required. Refer to AGENTS.md.

Preferred stack:

- React + TypeScript + Vite
- Tailwind CSS
- shadcn/ui or equivalent accessible component library
- Lucide icons
- React Router
- Recharts for dashboards
- localStorage for persistence
- Mock service layer for simulated backend operations

If an existing repository already has a suitable stack, preserve it rather than unnecessarily rebuilding everything.

## Application Architecture

The website must contain four independent but connected modules:

1. Uniform Management
2. Document Lookup
3. Locker Management
4. Purchase Support

A shared AI assistant must be accessible throughout the application.

Users should primarily interact with conventional dashboards, forms, tables, search interfaces, and approval screens. The chatbot is an additional interface, not a replacement for the application.

## Core Requirements

- Every module must have realistic sample data and working interactions.
- Forms must validate input and update application state.
- Changes must persist across refreshes using localStorage.
- Related modules must share consistent data.
- Support realistic employee, department, product, inventory, and supplier relationships.
- Simulate role-based access control and multi-party approvals.
- Include activity history and audit logs.
- Provide realistic Vietnamese interface text.
- Clearly identify simulated functionality where appropriate.
- Never imply that the application is connected to real Vinmec systems.

## Simulated AI

Implement a deterministic, local AI-assistant simulation.

It should:

- Recognize common Vietnamese user intents.
- Route queries to relevant modules.
- Search mock documents and display citations.
- Query uniform inventory and employee issuance history.
- Query locker availability.
- Search and suggest supplier product codes.
- Explain validation failures and approval statuses.
- Handle unsupported questions gracefully.

Do not integrate real LLM APIs. Do not pretend the assistant has general intelligence or fabricate information outside the mock dataset.

## Additional Product and Implementation Constraints

### 1. MVP Prioritization

The proposal explicitly prioritizes Uniform Management and Document Lookup for the five-week prototype.

Implement all four modules for demonstration purposes, but allocate implementation depth as follows:

- **Uniform Management:** Complete, end-to-end interactive workflow.
- **Document Lookup:** Complete document search, permission-aware retrieval, and citation-based assistant interaction.
- **Purchase Support:** Functional purchasing workflow integrated with Uniform Management, using simulated SAP services.
- **Locker Management:** Functional CRUD, availability search, assignment, and allocation, with less emphasis on advanced features.

Do not sacrifice the quality of the two priority modules to implement unnecessary features elsewhere.

### 2. Business Rules

All business rules must be implemented as deterministic application logic, not AI-generated decisions.

- Uniform issuance limit: configurable, default 3 sets per employee per year.
- Reserve purchasing limit: configurable, default 40% of employee headcount at one set per employee.
- The exact interpretation of annual limits and reserve calculations is not fully specified. Document the chosen assumptions and make the rules configurable.
- Historical issuance prices must remain unchanged when current product prices change.
- Employee roles determine eligible uniform categories.
- Inventory must never become negative.
- Stock must only change after the appropriate confirmed business action.
- Multi-party approvals must enforce required approval stages.

### 3. Purchasing Workflow

Distinguish between:
- Uniform requests
- Purchase requisitions
- Approval decisions
- Purchase orders
- Goods receipt
- Inventory updates

Simulated SAP integration must operate through a dedicated mock adapter so it can theoretically be replaced with real APIs in the future.

Do not imply that real SAP connectivity has been verified.

### 4. Document Retrieval

Create realistic fictional Vietnamese documents with meaningful searchable content.

Include:
- Internal administrative regulations
- Uniform issuance policies
- Purchasing procedures
- Fictional supplier contracts
- Locker assignment regulations

Documents should contain sections, dates, versions, and realistic procedural information.

The AI assistant must cite actual passages from these documents.

Document permissions must be enforced before retrieval, not merely by hiding results in the UI.

### 5. Data Consistency

Create one coherent fictional hospital dataset shared across all modules.

Avoid disconnected hardcoded dashboard statistics or chatbot responses.

Every displayed quantity, status, and historical record should derive from the same underlying application state.

### 6. Prototype Scope

This is a simulated demonstration, not a production system.

Security controls, RBAC, audit logs, and approvals are functional simulations. Client-side localStorage cannot provide production-grade security.

No real patient data, employee records, contracts, hospital credentials, or SAP connections should be used.

All fictional data should be clearly identifiable as demo data.

Preserve all important requirements from the proposal.

If the proposal is ambiguous, make reasonable assumptions, document them, and proceed.
