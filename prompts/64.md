# Phase 6.4 — AI Assistant UX and Cross-Module Integration

## Role

Act as a Senior AI Product Engineer and UI/UX Designer specializing in enterprise conversational interfaces.

The Vinmec Administrative Super App now has an OpenRouter integration, read-only application tools, and document RAG.

Your task is to make these capabilities usable, understandable, and reliable in the existing interface.

## 1. Read the project

Read:

- `AGENTS.md`
- `docs/ai-integration-plan.md`
- `docs/ai-openrouter-implementation.md`
- `docs/ai-rag-implementation.md`
- Existing assistant UI
- Existing module navigation
- Existing design system
- Existing tests

Use the installed UI/UX Pro Max skill if available.

Preserve the current visual identity and module functionality.

## 2. Environment configuration

Continue using the existing `.env` values:

- `OPENROUTER_API_KEY`
- `OPENROUTER_MODEL`

Do not hardcode either value.

The frontend must communicate with the existing server-side AI endpoint.

Never expose the API key in browser code, localStorage, or network responses.

## 3. Improve conversation UX

Implement or refine:

- Conversation history
- Clear user and assistant messages
- Loading indicators
- Request cancellation
- Error states
- Retry actions
- Follow-up questions
- Source references
- Tool-result presentation
- Empty-state suggestions
- Conversation reset

Ensure the interface works on desktop and mobile.

Preserve accessibility and keyboard navigation.

Do not expose raw tool-call JSON to ordinary users.

## 4. Make the assistant context-aware

The assistant should support questions across all four modules.

Examples:

Uniform Management:

"Áo blouse nữ cỡ L còn bao nhiêu?"

Follow-up:

"Thế cỡ XL thì sao?"

Purchase Support:

"Có đơn mua nào đang chờ phê duyệt?"

Follow-up:

"Đơn nào liên quan đến đồng phục?"

Locker Management:

"Còn tủ nào trống ở tầng 3?"

Document Lookup:

"Quy định cấp phát bổ sung đồng phục là gì?"

Follow-up:

"Cho tôi xem điều khoản liên quan."

The assistant should maintain conversational context without confusing different entities.

When context is ambiguous, ask for clarification.

## 5. Integrate source navigation

When a response references:

- A uniform product
- An inventory record
- An employee issuance record
- A purchasing request
- A purchase order
- A locker
- A document

Provide navigation to the relevant record or module where supported.

Use stable record identifiers.

Do not invent destinations.

For documents, citations should open the appropriate document version and section.

## 6. Present trustworthy answers

Distinguish between:

- LLM-generated explanations
- Retrieved document evidence
- Structured application data
- Deterministic fallback responses

Show clear error messages when data is unavailable.

Do not display fabricated inventory quantities or unsupported citations.

For sensitive or ambiguous requests, require clarification.

The assistant should explain eligibility or purchasing decisions using results from deterministic business rules.

## 7. Maintain application consistency

Verify that the assistant reflects changes made through normal UI workflows.

Examples:

- Issuing uniforms changes inventory.
- Receiving goods increases stock.
- Assigning lockers changes availability.
- Publishing a new document changes eligible retrieval sources.

The assistant must use the same current state as the application.

Do not introduce a duplicate dataset.

## 8. Preserve business workflow boundaries

The assistant may help users find information and navigate to forms.

It must not silently:

- Approve requests
- Issue uniforms
- Create purchase orders
- Receive goods
- Assign lockers
- Modify employee records

Keep these actions inside the existing validated UI workflows.

If a user requests an action, the assistant may explain the steps or navigate to the appropriate form.

## 9. Testing

Add or update tests for:

- Conversation context
- Clarification questions
- Source navigation
- Error handling
- Retry behavior
- Fallback mode
- Cross-module consistency
- Responsive layout
- Permission-aware presentation

Use Playwright for browser interaction and screenshot verification.

Run TypeScript checks, unit tests, and build.

## 10. Deliverables

Implement the UX improvements.

Update the relevant documentation.

Create `docs/ai-ux-verification.md`.

At completion, report:

- UI changes
- Cross-module interactions
- Navigation improvements
- Test results
- Remaining limitations

Do not proceed to Phase 6.5 automatically.
